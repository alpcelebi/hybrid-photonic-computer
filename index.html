ARCHITECTURE

System Architecture

An electronic host and a photonic accelerator connected through SRAM priority queues on a control die. Thin-film LiNbO₃ modulators carry the data into the light path. Packets flow by priority level.

COMPONENTS

System Components

Three subsystems with clear boundaries. All state lives in electronics, and the photonic core holds no state between passes.

⚡
Electronic Host
OS, Storage & Everyday Computing
Standard binary CMOS at ~0.7–0.9 V. Four-level logic at 3.3 V would cost ~19× more dynamic power and give a worse noise margin. Multi-level encoding is used only where it already works: MLC/TLC NAND storage. Existing software runs unchanged.

💡
Photonic Accelerator
Matrix Math for AI Inference
An N×N weight mesh in Si₃N₄ computes y = Wx with light. Inputs arrive as PAM-4 symbols at ~10 GBd per wavelength, and WDM runs many wavelengths in parallel. Lasers, tuning and converters still produce heat: the gain is efficiency, not zero heat.

Async Queues + E/O Bridge
Control Die
SRAM ring buffers hold the P0/P1/P2 submission and completion queues. LiNbO₃ cannot store data, because the Pockels effect lasts only while voltage is applied, so it is used where it excels: as the high-speed modulator. Preemption happens between tiles, so no optical memory is needed.

MATHEMATICS

4⁴ = 256, Reinterpreted: Base-4 Digit Slicing

The identity is not an advantage on its own. It becomes one when it decides how many light levels each optical pass must resolve.

Every power-of-two base maps exactly onto 256 values (2⁸ = 16² = 256), and an ordinary byte already does. Base 4 is useful elsewhere. Write an 8-bit input as four base-4 digits, x = Σ 4ᵏ·xₖ. Because optics is linear, Wx = Σ 4ᵏ·(W xₖ). Each pass then needs only 4 light levels instead of 256. That is PAM-4, already mass-produced for optical Ethernet. The control die recombines the four partial results by shift-and-add.

Cost: four passes per operand. Open problem: the output ADC still needs more precision than today's fast, low-energy converters provide.

ENERGY MODEL

Where the Gains Really Come From

EMAC = D·[(EDAC+EADC)/N + PL/(f·N²) + PT/(f·M·N²)], with N = 64, f = 10 GBd and D = 4 passes. Every value is an illustrative placeholder to be replaced with device data.

🔥
Tuning Decides Everything
Thermo-optic weights on a single wavelength spend ~781 fJ per MAC on heater power alone. The photonic core ends up worse than a GPU.
GPU ~707 fJ→879 fJ0.8× (worse)
🌈
WDM Amortises Tuning
Sixteen wavelengths share the same tuned mesh. That cuts the tuning cost 16× and raises throughput to ~164 TMAC/s per core.
879 fJ→147 fJ4.8× vs GPU
⚡
Electro-Optic Weights
Thin-film LiNbO₃ or non-volatile phase-change weights hold their state with almost no power. Conversion (DAC + ADC) then dominates.
GPU ~707 fJ→~98–103 fJ~7× less
🏭
Facility-Level Bound
Only the matrix-math share of facility energy (assumed 50%) gets cheaper. Amdahl's law caps the total saving.
100%→~57%≤ ~43% less
💧
Cooling Water
Cooling water scales with the heat rejected, so it follows the same bound, not the 90% claimed in v1.0. Baseline: ~500 ml per ~10–50 responses for a GPT-3-class model (Li et al., 2023).
100%→≥ ~57%≤ ~40% less
🧠
What Is Not Claimed
No training speed-up, because precision is too low. No latency miracle, because memory traffic and token-by-token decoding remain. No THz clock: the symbol rate is ~10 GBd.

TRADE-OFFS

Advantages & Disadvantages

What this architecture gets right, and where the hard engineering problems remain.

✓ Advantages
⚡
~5–7× Lower Energy per MAC (Best Case)
With electro-optic or non-volatile weights, or with WDM, the photonic core reaches ~100–150 fJ per 8-bit MAC, against ~700 fJ on a current GPU.
📶
Proven Optical Format
Base-4 digit slicing needs only PAM-4, already mass-produced for 400G/800G optical links, instead of an impractical 256-level signal.
⏸
Preemption Without Optical Memory
Each optical pass is stateless and all state stays in electronic SRAM, so urgent P0 jobs preempt at the next tile boundary.
🔀
Independent Scaling
Async queues let accelerator cores be added without changing the host software.
💻
Existing Software Runs As-Is
The host is ordinary binary CMOS. Only a driver, a runtime and a compiler back-end are new, just as for any GPU or NPU.
🛡
Fault Isolation
If the accelerator fails, the host keeps running and jobs can fall back to electronic execution.
✗ Disadvantages
🎯
Output Precision
Accumulating 64 products exactly needs ~11.5 bits, but fast low-energy ADCs give ~6. This is the central open problem.
🔥
Tuning Power & Reprogramming
Thermo-optic weights waste power and change slowly, electro-optic weights take up a lot of area, and phase-change weights wear out.
🧱
Memory Wall Unchanged
Weights and activations still come from host memory, which dominates many inference workloads.
🔧
Integration & Packaging
The photonic core, control die and lasers must be co-packaged with dense optical and electrical I/O.
📉
Modest Throughput per Core
10–164 TMAC/s per core, against ~990 TMAC/s for a GPU, means many cores per package.
💸
High Cost & Niche Talent
Photonic components are not mass-produced at this scale, and photonic engineers are scarce.
SPACE · SPECULATIVE

Possible Space Advantages, With Caveats

Version 1.0 claimed immunity to radiation and solar storms. That was wrong: the detectors, lasers, converters and host are still electronics. What remains are partial advantages that would need radiation testing.

Radiation-hardened spacecraft processors, like the RAD750 on Mars rovers, run at ~200 MHz because protecting transistors against particle strikes costs speed and density.

A photonic accelerator could help in two limited ways. The waveguides themselves do not suffer charge-deposition bit flips, and cheaper matrix math stretches tight power budgets. Everything around the light path still needs hardening: photodetectors, lasers, ADCs, the control die and the host. Optical materials also darken under radiation.

Key Space Numbers

☄️
Fewer Upsets in the Optical Path
Photons carry no charge, so the waveguide mesh itself does not suffer single-event upsets. Photodetectors, lasers and converters still do, and radiation-induced attenuation degrades optical materials over time.
Partial advantage · requires radiation testing
⚡
Stretching Power Budgets
Outer-planet probes run on RTGs producing ~100–300 W. A core that does matrix math ~5–7× more cheaply could allow more on-board inference within the same budget.
Benefit limited to the matrix-math share of compute
🌡️
Less Heat, Not Zero Heat
In vacuum, heat leaves only by radiation. Lasers (~10–30% efficient), tuning and converters still dissipate power, so radiators shrink in proportion to the energy saved. They do not disappear.
Radiator savings scale with energy saved
🤖
On-Board Autonomy
With a 3–22 minute signal delay to Mars, rovers must decide locally. More efficient inference helps, but the gain is a few times, not the 5,000× claimed in v1.0.
A few × more inference per watt (estimate)
DATA FLOW

Async Pipeline

The host submits a job and continues. If the queue is full it gets BUSY (backpressure) instead of blocking. The control die schedules by priority, runs the optical passes, and posts the result with an interrupt.
